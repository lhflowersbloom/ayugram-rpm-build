AyuGram RPM for Fedora

AyuGram Desktop gives you Ghost mode, anti-recall and heavier customisation on top of Telegram. Upstream only ships macOS and Windows builds — for Linux it publishes source. These RPMs are compiled from that source on GitHub Actions and smoke tested with a real dnf install.

  • x86_64
  • static Qt
  • built from source
  • GPL-3.0-or-later

Install

Download the latest RPM Source repository
# two options, both single commands sudo dnf install ./ayugram-desktop-<version>.x86_64.rpm # local file sudo dnf install https://github.com/lhflowersbloom/ayugram-rpm-build/releases/latest/download/ayugram-desktop-<version>.fc45.x86_64.rpm # straight from the release

Launch it with ayugram-desktop or from the app menu as AyuGram Desktop. No repository to add, no Flatpak runtime to pull.

Same package name as the RPM Fusion build. RPM Fusion also ships an ayugram-desktop package, so dnf treats this file as the same package rather than a second one — remove the RPM Fusion build first if you want to switch, and do not expect the two to coexist.

Why build it yourself

  • Upstream has no Linux binary. AyuGram publishes .dmg and .zip only; Linux users are pointed at the source. This closes that gap with a real package.
  • Static Qt, low dependency surface. The binary is linked against a static Qt, so the RPM does not chase Fedora's Qt updates between releases. Runtime needs are pinned by soname plus glibc ≥ 2.28.
  • Verified, not assumed. Every package is installed with dnf inside a clean fedora:latest container, so soname resolution and linking are actually exercised before a release is published.
  • A portable fallback. Each release also carries AyuGram-<version>-linux-x86_64.tar.gz — same binary, no install needed.

How it is built

upstream releases/latest ──▶ already packaged? ──yes──▶ stop (10 s) │no ▼ clone upstream ──▶ build libtlottie.a ──▶ cmake + ninja ──▶ strip ──▶ rpmbuild ──▶ dnf install in fedora:latest ──▶ GitHub release

A scheduled workflow checks upstream every day at 20:00 UTC (04:00 Asia/Shanghai) and only runs the full build when it finds a version without a build-<version>-N tag here. The compile itself takes roughly 110 minutes on a 4-core runner, so the stripped binary is uploaded as an artifact the moment it is built — a packaging failure never costs a second two-hour compile.

Questions

Is this the same as the RPM Fusion package?

No, they are independent builds from the same upstream source with different Qt linkage and dependency pinning. They share the package name ayugram-desktop, so install one or the other — not both.

Why not just use the Flatpak or the AppImage?

Use whichever fits. The reason this exists is that no Fedora-native RPM of the current upstream release was available, and a package that dnf resolves and tests is easier to reason about than a portable binary.

Does Ghost mode mean my account is safe?

No. AyuGram uses the official Telegram API credentials and pretends to be a regular client, but you are still running an unofficial client — use it at your own risk. This page only packages what upstream publishes; it does not change behaviour.

How do I uninstall it?

sudo dnf remove ayugram-desktop. Session data lives under ~/.local/share and is untouched by the package.
